# ADR 0001 — Reverse-proxy: Traefik, а не Caddy

**Статус:** принято · 2026-08-26

## Контекст
Владелец предполагал поставить Caddy («либо ещё что получше») и выпустить
сертификаты. Фактическая проверка сервера показала: на `:80`/`:443` **уже
работает Traefik** — `/docker/traefik/docker-compose.yml`, `network_mode: host`,
docker-провайдер с `exposedbydefault=false`, ACME-резолвер `letsencrypt`
(HTTP-challenge), автоматический редирект 80→443.
DNS обоих доменов уже указывает на `203.0.113.10`.

## Решение
Caddy/nginx **не ставим**. Используем существующий Traefik. Маршрут появляется
добавлением лейблов к нашему контейнеру, сертификат выпускается автоматически.

## Последствия
- Плюс: ноль изменений в общей инфраструктуре, ноль риска конфликта за порты.
- Плюс: сертификаты и продление — уже решённая задача.
- Минус: мы зависим от чужого конфига Traefik. Если его перезапустят/сломают,
  ляжет и наш стенд.
- Минус: docker-провайдер видит **только контейнеры**. См. ниже.

## Как выставить dev-стенд — РЕШЕНО: вариант A

По ТЗ dev — systemd-служба на хосте с hot-reload. Docker-провайдер Traefik
такие сервисы не обнаруживает. Три варианта:

| | Вариант | Плюсы | Минусы |
|---|---|---|---|
| **A** | Добавить Traefik **file-провайдер**: `--providers.file.directory=/etc/traefik/dynamic` + монтирование каталога. Маршрут на `127.0.0.1:3001`. | dev остаётся systemd, как и просил владелец; правка аддитивная | нужен рестарт Traefik (кратковременный простой); мы меняем общий конфиг |
| **B** | Запускать dev тоже в Docker с bind-mount исходников; hot-reload работает через `tsx watch` / `next dev` внутри контейнера | ноль изменений в Traefik | расходится с ТЗ («dev = системная служба»); чуть медленнее итерации |
| **C** | Контейнер-прокси с лейблами, проксирующий на `host.docker.internal` | ноль изменений в Traefik, dev остаётся на systemd | лишняя движущаяся часть |

**Выбран вариант A** (подтверждено владельцем 2026-08-26).

Правка аддитивная: docker-провайдер продолжает работать без изменений, dev
остаётся systemd-службой с hot-reload — ровно та топология, которую описал
владелец. На момент правки Traefik не обслуживал ничего постороннего
(единственный контейнер на сервере — он сам), поэтому рестарт был бесплатен.

### Что именно изменено в `/docker/traefik/docker-compose.yml`

Добавлено (бэкап оригинала — рядом, с суффиксом `.bak-mqbot`):

```yaml
command:
  # ...существующие флаги без изменений...
  - --providers.file.directory=/etc/traefik/dynamic
  - --providers.file.watch=true
volumes:
  # ...существующие тома без изменений...
  - /docker/traefik/dynamic:/etc/traefik/dynamic:ro
```

Динамический конфиг маршрутов dev-стенда — `/docker/traefik/dynamic/mqbot-dev.yml`
(копия под версионным контролем: `infra/traefik/mqbot-dev.yml`).
`watch=true` означает, что правка маршрутов **не требует рестарта Traefik**.

Так как Traefik работает в `network_mode: host`, он ходит в dev-сервисы
напрямую на `127.0.0.1` — сервисы наружу не публикуются.

### Откат
Восстановить `.bak-mqbot`, удалить `/docker/traefik/dynamic`,
`docker compose up -d` в `/docker/traefik`.
