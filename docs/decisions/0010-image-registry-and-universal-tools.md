# ADR 0010 — Реестр картинок и универсальные инструменты

**Статус:** принято · 2026-08-27
**Отменяет:** `restyle_photo`, `transform_world`, `list_professions`,
`ToolContext.lastImageUrl`, `ToolContext.currentImageUrl`,
`buildProfessionPrompt`, `buildWorldPrompt`.

## Что не так

Владелец, разбирая живой прогон: инструментов много, а главного бот не умеет —
понять, **какую именно картинку** его просят изменить.

Разбор показал, что дело не в количестве инструментов. Две причины, обе
архитектурные.

### 1. Ни у одного инструмента нет параметра «какую картинку»

```
edit_photo(change, aspect_ratio, caption)
restyle_photo(profession, extra_idea, caption)
transform_world(change, caption)
```

Картинку выбирал backend по эвристике в `runner.ts`. Модель не могла
ошибиться в выборе — **ей не давали выбирать**. Любая её догадка всё равно
отбрасывалась.

Отсюда дефект 27.08: участник прислал новое фото, попросил «сделай ночь» —
ночь легла на генерацию 22-минутной давности, потому что эвристика
«в этом сообщении фото нет → бери последний результат» не сравнивала время.

### 2. Модель не видела ни одной картинки, кроме самой свежей

`runner.ts` собирал историю только из текста:

```ts
const priorMessages = history
  .filter((m) => m.role !== 'system' && (m.text ?? '').length > 0)
  .map((m) => ({ role: ..., text: m.text ?? '' }));   // ← imageUrls теряются
```

То есть в диалоге «кот → кот в шляпе → собака → собака на море» модель на
четвёртом шаге не видела ни кота, ни собаки. Она ориентировалась по
собственным старым репликам («это акварельный замок на холме») — вслепую.

Никакая смена модели или доводка описаний инструментов это не чинит.

## Решение

### Реестр картинок диалога

Каждая картинка получает короткий id (`img1`, `img2`, …), присвоенный
хронологически. Источники — то, что уже лежит в БД:

| Откуда | Что становится картинкой |
|---|---|
| `messages.content_json.imageUrls` | фото, присланные участником |
| `generations` этого диалога | всё, что мы для него нарисовали |
| `users.current_world_media_id` | выданный стартовый мир |

Реестр **выводится**, а не хранится отдельной таблицей: единственный источник
правды остаётся прежним, рассинхрону взяться неоткуда.

### Модель их видит

Последние `agent.imagesInContext` картинок (по умолчанию 6) прикладываются
к запросу — каждая отдельным служебным сообщением со своим id:

```
[img1] Фото, которое прислал участник.        <картинка>
[img2] Мы сделали для участника: «кот в шляпе». <картинка>
```

Картинки старше окна остаются в списке строкой, но без вложения — чтобы
на них всё ещё можно было сослаться.

Замер на наших прогонах: одна фотография добавляет ~1,5–6 тысяч входных
токенов, в зависимости от размера файла. Шесть картинок — верхняя граница,
за которой контекст дороже пользы. Кэширование промпта работает: история
append-only, префикс стабилен.

### Выбор делает модель

У `edit_image` появляется **обязательный** `image_id`. Неизвестный id —
не исключение, а нормальный `ok: false` со списком доступных; модель
исправляется сама, без участия человека.

## Набор инструментов: 8 → 5

| Было | Стало |
|---|---|
| `generate_image` | `generate_image` — без изменений |
| `edit_photo` | `edit_image` — + `image_id` |
| `restyle_photo` | ↳ то же самое: «одень его космонавтом» — это правка картинки |
| `transform_world` | ↳ то же самое: мир — обычная картинка в реестре |
| `list_professions` | ↳ 12 названий уезжают в системный промпт: без вызова, без задержки |
| `get_base_world` | `get_base_world` — остаётся: выдача из пула мгновенна и бесплатна |
| `get_balance` | `get_balance` |
| `suggest_replies` | `suggest_replies` |

### Что было ценного в удалённых инструментах и куда делось

- **Сохранение лица** (`buildProfessionPrompt`) — переехало в общий
  `buildEditPrompt`: теперь применяется к любой правке, где есть человек,
  а не только к сценарию «профессия». Так надёжнее: раньше «перекрась мне
  куртку» лицо не защищало вообще.
- **Заготовки промпта по профессиям** — удалены. Агент пишет описание сам;
  каталог остаётся в БД как источник названий для подсказок и для админки.
- **«Меняй только названное»** (`buildWorldPrompt`) — тоже в `buildEditPrompt`,
  теперь распространяется на все правки.

## Схема БД

Миграция 0006:

- `media.remote_url`, `media.remote_url_expires_at` — кэш заливки в kie.ai.
  Без него шесть картинок в контексте означали бы шесть заливок на каждое
  сообщение. Ссылки kie.ai живут 14 дней, кэш живёт столько же.
- `generations.conversation_id` — генерации не были связаны с диалогом
  вообще (`tool_call_id` проставить нечем: строка вызова пишется уже после
  цикла агента).
- `generations.source_url` — какая картинка реально ушла в модель.
  Источник дефекта 27.08 пришлось выяснять запросом в kie.ai, потому что у
  нас он нигде не записан. В админке (фаза 9) это обязано быть видно.
- `users.current_world_at` — когда выдан стартовый мир, чтобы он встал в
  реестр на своё место по времени.

## Чем платим

- Контекст дороже: до шести картинок вместо одной. Это осознанно — слепой
  агент дешевле, но он ошибается, а ошибка стоит участнику генерации и токена.
- Модель обязана назвать `image_id`. Промахи возможны, но они **видимые** и
  поправимые: инструмент возвращает список и объясняет, что не так.
  Прежняя эвристика ошибалась молча.
