# ADR 0003 — Агент вместо меню

**Статус:** принято · 2026-08-26

## Контекст
Главное требование владельца: бот должен быть **простым** — без кнопок, меню и
каскадов. ТЗ тоже требует «максимально просто и быстро». Классический
telegram-бот на FSM («выберите профессию» → «пришлите фото» → …) этому
противоречит: это и есть каскад.

## Решение
Бот — **один диалог с LLM-агентом**, у которого есть набор инструментов.
Намерение распознаёт модель, а не дерево кнопок. Состояние живёт в истории
диалога, а не в конечном автомате.

Кнопки допустимы **только** как необязательный ускоритель. Инвариант: если
убрать все кнопки, каждый сценарий обязан проходиться чистым текстом.

## Последствия
- Плюс: пользователь может передумать, уточнить, попросить переделать —
  всё это агент обрабатывает без отдельного кода на каждый переход.
- Плюс: новый сценарий = новый tool, а не новая ветка FSM.
- Минус: каждое сообщение стоит вызова LLM → расходы и задержка.
  → Митигация: короткий контекст (20 сообщений / 30 минут), лимит 8 итераций
  tool-use цикла.
- Минус: недетерминированность. Агент может выбрать не тот tool.
  → Митигация: ортогональные инструменты с явными «когда НЕ вызывать»;
  все `tool_calls` пишутся в БД и видны в админке — это основной инструмент
  отладки поведения.
- Минус: prompt injection через пользовательский ввод.
  → Митигация: инструменты не выполняют произвольный код; списание токенов и
  проверки прав — вне LLM, в обычном коде.
