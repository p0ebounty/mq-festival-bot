# ADR 0008 — Мозг агента: вынужденный отказ от Claude на kie.ai

**Статус:** принято · 2026-08-26

## Что случилось

ADR 0002 закладывал мозг агента на Anthropic-совместимый эндпоинт kie.ai
(`/claude/v1/messages`, `claude-sonnet-5`). При переходе к реализации
выяснилось, что **эндпоинт не работает**.

## Проверено фактически (26.08.2026)

`POST https://api.kie.ai/claude/v1/messages` → **HTTP 500**
`{"type":"error","error":{"type":"api_error","message":"Server exception, please try again later"}}`

Одинаково для `claude-sonnet-5`, `claude-opus-5`, `claude-haiku-4-5`,
`claude-sonnet-4-6`, `claude-opus-4-8`; по несколько попыток с паузами.
При этом Jobs API (картинки) и `/api/v1/chat/credit` работают нормально —
значит ключ и аккаунт в порядке, лежит именно Claude-прокси.

## Что у kie.ai реально доступно для чата

Остальные чат-модели живут по **другому пути и в формате OpenAI**:
`POST https://api.kie.ai/{model}/v1/chat/completions`.

Прогон всех моделей из их каталога с одинаковым сценарием
(системный промпт фестиваля → просьба «сделай меня космонавтом» →
вызов инструмента → возврат результата → ответ участнику):

| Модель | Итог |
|---|---|
| **gemini-3-flash** | ✅ вызвала инструмент, ответила по-русски. **17.7 с**, 432 токена |
| **gemini-3-pro** | ✅ вызвала инструмент, ответила по-русски. **20.4 с**, 634 токена |
| gpt-5-2 | доступна, но **инструмент проигнорировала**; 38 с на один виток |
| gpt-5-4, gpt-5-5, gpt-5-6-luna/sol/terra | ❌ `{"code":422,"msg":"The model is not supported"}` |
| gemini-3-7-flash, gemini-3-1-pro, gemini-2-5-pro | ❌ `The model is not supported` |
| все claude-* | ❌ HTTP 500 |

⚠️ Ловушка: недоступные модели отвечают **HTTP 200** с телом
`{"code":422,"msg":"The model is not supported"}`. Проверять только статус
недостаточно — это та же особенность, что и у Jobs API.

**Вывод по OpenAI:** через kie.ai это не вариант. Из шести моделей GPT-5
доступна ровно одна, и она не умеет вызывать инструменты.

## Решение

1. **Мозг агента — `gemini-3-flash`** по умолчанию, `gemini-3-pro` как
   альтернатива (обе настраиваются в админке, поле уже есть).
   Flash втрое дешевле ($0.15/$0.90 против $0.50/$3.50 за 1M) и чуть быстрее;
   качество ответа на нашем сценарии сопоставимое.
2. **Провайдер за интерфейсом.** `packages/core/src/agent/providers/` —
   адаптер OpenAI-совместимого чата (работает сейчас) и заготовка под
   Anthropic. Цикл tool-use провайдеро-независим; отличается только
   формирование запроса и разбор ответа.
3. Когда kie.ai починит Claude — переключение будет сменой строки в
   настройках, без переписывания агента.

## Важное наблюдение про зацикливание

В первом тесте `gemini-3-flash` на втором витке вызвала инструмент повторно
вместо ответа. Причина оказалась **в промпте, а не в модели**: системный
промпт говорил «если просят картинку — вызывай инструмент», и модель честно
выполняла это снова. После добавления строки «после вызова инструмента НЕ
вызывай его повторно — просто скажи участнику, что делаешь» поведение стало
корректным у обеих моделей.

Отсюда правило: **защита от зацикливания — это и промпт, и жёсткий лимит
итераций в коде.** Одного лимита мало: он спасает от бесконечности, но
участник получит бессмысленный ответ. См. `.claude/rules/20-bot-agent.md`.

## Последствия

- Минус: теряется преимущество «официальный SDK Anthropic» из ADR 0002.
  Пишем свой тонкий клиент под OpenAI-совместимый формат.
- Минус: нет промпт-кэширования Anthropic → расчёт экономии из ADR 0006
  завышал экономию. Пересчёт: при ~10k входных токенов на запрос
  gemini-3-flash даёт ≈ $0.0019 за запрос — всё равно дешевле любого
  варианта с Claude.
- Плюс: сохраняется главное требование владельца — **один ключ и один
  провайдер** на картинки и на диалог.
- Плюс: цена мозга упала втрое против плана.
- Риск: kie.ai сам предупреждает, что стабильность «чуть ниже официальных
  провайдеров». Мы это уже увидели на Claude. Митигация — интерфейс
  провайдера и возможность увести мозг на прямой ключ Anthropic/OpenAI,
  если владелец захочет.

## Открытый вопрос владельцу

Если нужен именно Claude или именно OpenAI — потребуется **отдельный ключ
напрямую у провайдера** со своим биллингом. Это ломает «один ключ на всё»,
но снимает зависимость от прокси kie.ai для самой важной части бота.
