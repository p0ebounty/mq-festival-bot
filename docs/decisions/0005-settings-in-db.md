# ADR 0005 — Настройки: `.env` против БД

**Статус:** принято · 2026-08-26

## Контекст
Требование владельца: «чтобы можно было быстро изменить ключ провайдера, чтобы
быстро перепрыгнуть». Если ключ живёт только в `.env`, смена требует правки
файла и рестарта — на фестивале это неприемлемо.

## Решение
Двухуровневая конфигурация.

**`.env`** — то, без чего процесс не стартует:
`DATABASE_URL`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`,
`SECRETS_ENC_KEY`, `PUBLIC_URL`, `ADMIN_SESSION_SECRET`.

**БД (таблица `settings`)** — то, что меняется на лету из админки:
ключ kie.ai, выбранные модели, экономика токенов, системный промпт агента.

Приоритет: значение из БД **перекрывает** `.env`. `KIE_API_KEY` в `.env` —
только bootstrap на случай пустой базы.

## Безопасность
- Секретные значения в `settings` шифруются AES-256-GCM ключом `SECRETS_ENC_KEY`.
- Наружу (в API админки) отдаётся **только маска** вида `sk-…abcd`.
  Полное значение не покидает сервер никогда.
- Смена ключа пишется в `audit_log`.
- ⚠️ Потеря `SECRETS_ENC_KEY` = потеря всех зашифрованных настроек.
  Ключ обязан попасть в бэкап отдельно от дампа БД.

## Последствия
- Плюс: смена ключа — без рестарта и без доступа к серверу.
- Плюс: кнопка «Проверить ключ» (`GET /api/v1/chat/credit`) подтверждает
  работоспособность до того, как его увидят пользователи.
- Минус: значение настройки теперь в двух местах — нужен один явный резолвер
  (`packages/config`), а не чтение `process.env` по всему коду.
