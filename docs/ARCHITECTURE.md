# Архитектура

## Схема

```
Telegram ──webhook──┐
                    ▼
        ┌───────────────────────────┐
        │  Traefik (:80/:443, ACME) │   уже развёрнут на сервере
        └───────────┬───────────────┘
                    │  bot.example.com / bot-dev.example.com
        ┌───────────┴───────────────┐
        │                           │
   /tg/*  /api/*  /g/*              │  /
        ▼                           ▼
┌──────────────────┐        ┌────────────────┐
│  apps/bot        │        │  apps/admin    │
│  Fastify+grammY  │        │  Next.js       │
└────────┬─────────┘        └───────┬────────┘
         │                          │
         │  @mq/core  @mq/db        │
         ▼                          ▼
   ┌──────────────┐          ┌──────────────┐
   │ PostgreSQL   │          │ media storage│
   └──────────────┘          └──────────────┘
         │
         │  Anthropic SDK (baseURL=api.kie.ai/claude)  → агент
         │  Jobs API (api.kie.ai/api/v1/jobs)          → картинки
         ▼
   ┌──────────────┐
   │   kie.ai     │ ──callback──► /api/kie/callback
   └──────────────┘
```

## Монорепо

```
apps/
  bot/       Fastify + grammY: вебхук, REST для админки, /g/ страницы, callback kie.ai
  admin/     Next.js App Router: веб-интерфейс администратора
packages/
  core/      агент, tools, клиент kie.ai, storage, QR, промпт-билдеры
  db/        Drizzle: схема, миграции, репозитории
  config/    типизированный env + слой настроек из БД
```

Почему `bot` держит и Telegram, и REST, и публичные страницы: один процесс — один
домен — один сертификат, меньше движущихся частей. Админка (Next.js) — отдельный
процесс, потому что у неё свой рантайм и свой цикл сборки.

## Ключевое решение: один провайдер на всё

kie.ai отдаёт и чат-модели (Anthropic-совместимый `/claude/v1/messages` с полной
поддержкой `tools`), и генерацию картинок (Jobs API). Значит:

- **один API-ключ** на мозг агента и на картинки;
- смена ключа в админке чинит сразу всё;
- на клиенте — официальный `@anthropic-ai/sdk` с подменённым `baseURL`,
  никаких самописных HTTP-обёрток для чата.

## Поток генерации (асинхронный)

```
пользователь пишет
   → агент решает вызвать tool
   → списываем токены, пишем generations(status=pending)
   → POST /api/v1/jobs/createTask  { model, input, callBackUrl }
   → сразу получаем taskId, tool возвращает агенту "accepted"
   → агент отвечает пользователю «делаю, ~30 сек»
   ...
   → kie.ai POST /api/kie/callback  (подпись проверяется)
   → скачиваем результат к себе, генерируем shortId + QR
   → досылаем пользователю картинку + QR отдельным сообщением
   → generations(status=success)
```

Polling по `GET /api/v1/jobs/recordInfo?taskId=` — **резервный** путь: воркер
добирает задачи, по которым callback не пришёл за 90 секунд.
Состояния задачи: `waiting | queuing | generating | success | fail`.

## Модель данных (черновик)

| Таблица | Назначение |
|---|---|
| `users` | участники Telegram: tg_id, имя, язык, баланс токенов, бан |
| `conversations` / `messages` | история диалога с агентом |
| `tool_calls` | какой tool, аргументы, результат, длительность — для админки |
| `generations` | исходный запрос, **финальный промпт**, taskId, статус, стоимость, медиа |
| `media` | файлы: путь, тип, хеш, TTL |
| `short_links` | shortId → generation, для QR |
| `social_claims` | скрины репостов, статус модерации, perceptual hash |
| `professions` | каталог профессий |
| `base_worlds` | пул базовых миров для сценария 2 |
| `settings` | ключ kie.ai (шифрованный), модели, экономика, системный промпт |
| `admin_users` | администраторы (argon2id) |
| `audit_log` | действия администратора |

## Настройки: .env vs БД

- `.env` — то, без чего процесс не стартует: `DATABASE_URL`, `TELEGRAM_BOT_TOKEN`,
  `WEBHOOK_SECRET`, `SECRETS_ENC_KEY`, `PUBLIC_URL`.
- **БД** — то, что меняется на лету из админки: ключ kie.ai, выбранные модели,
  экономика токенов, системный промпт агента.

`KIE_API_KEY` в `.env` — только bootstrap. Как только ключ введён в админке,
приоритет у значения из БД. Значение в БД шифруется AES-256-GCM.
