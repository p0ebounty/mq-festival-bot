## 🔑 Контрольная точка после фазы 3

После фазы 3 работа **останавливается**. К этому моменту:

- `https://bot-dev.example.com` открывается по HTTPS,
- там работает вход в админку (аккаунт `admin`),
- есть страница **Настройки** с полем ключа kie.ai и кнопкой «Проверить ключ».

**Действие владельца:** зайти в админку и ввести ключ kie.ai.
Кнопка «Проверить ключ» дёргает `GET /api/v1/chat/credit` и показывает
остаток кредитов — это подтверждает, что ключ рабочий.

Без ключа фазы 4+ невозможны: и мозг агента, и генерация картинок ходят
через kie.ai.

**Ещё понадобится к фазе 5:** два токена от @BotFather — для dev-бота и
для prod-бота. Их можно прислать заранее, они кладутся в `.env` каждого стенда.

## Фазы

### Фаза 0 — Фундамент
Структура репозитория, `CLAUDE.md`, правила в `.claude/rules/`, разбор ТЗ,
ADR, зеркало документации kie.ai, установка тулчейна и скиллов.
**DoD:** новый чат может продолжить работу, прочитав `CLAUDE.md` + `docs/STATE.md`.

### Фаза 1 — Каркас и инфраструктура
pnpm workspace, TypeScript strict, ESLint/Prettier, Vitest.
PostgreSQL в Docker на `127.0.0.1:5432`, базы `mqbot_dev` / `mqbot_prod`.
Fastify с `/api/health`. Маршрутизация обоих доменов через Traefik, TLS.
**DoD:** `curl https://bot-dev.example.com/api/health` отдаёт 200 с валидным сертификатом.

### Фаза 2 — БД и слой настроек
Drizzle: схема из `ARCHITECTURE.md`, миграции, репозитории.
Шифрованное хранилище настроек (AES-256-GCM), сидинг дефолтов.
**DoD:** миграции применяются с нуля; настройка пишется и читается зашифрованной.

### Фаза 3 — Админка: вход + настройки  ⬅️ ОСТАНОВКА
Next.js + Tailwind + shadcn/ui, тёмная/светлая тема.
Вход по паролю (argon2id), сессия в httpOnly-cookie, rate limit.
Страница «Настройки»: ключ kie.ai (маскированный), кнопка «Проверить ключ»,
выбор моделей, параметры экономики.
Линт-правила против нативных `alert/confirm/prompt/<select>`.
**DoD:** владелец входит в админку на dev-домене и сохраняет ключ; «Проверить
ключ» показывает остаток кредитов.

### Фаза 4 — Клиент kie.ai
`packages/core/kie`: `createTask`, `recordInfo`, обработка кодов
(401/402/422/429/501...), ретраи с backoff, соблюдение лимита 20 задач/10 сек.
Приём callback с проверкой подписи. Воркер-добор для потерянных callback.
Storage-адаптер: скачивание результата к себе (медиа kie.ai живёт 14 дней).
**DoD:** тестовая задача проходит путь createTask → callback → файл на диске.

### Фаза 5 — Бот и ядро агента
grammY на вебхуке, приём текста и фото. Anthropic SDK на `api.kie.ai/claude`.
Tool-use loop (лимит 8 итераций), сборка контекста, персист диалога и
`tool_calls`. Системный промпт из настроек.
**DoD:** бот отвечает осмысленно, вызывает тестовый tool, диалог виден в БД.

### Фаза 6 — Инструменты и сценарии ТЗ
`generate_image`, `edit_image`, `get_base_world`, `get_balance`,
`suggest_replies`. Промпт-билдер с правилом сохранения авторского посыла.
Пул стартовых миров. Реестр картинок диалога: выбор картинки для правки
делает модель по id, а не backend по эвристике (ADR 0010).
**DoD:** оба сценария ТЗ проходятся end-to-end **чистым текстом**, без кнопок.

### Фаза 7 — QR-коды и страница шаринга
shortId, генерация QR, публичная страница `/g/<shortId>`: картинка,
скачивание, готовые хештеги фестиваля, «Лидер», MagnaQore.
**DoD:** QR из Telegram сканируется телефоном и открывает рабочую страницу.

### Фаза 8 — Экономика токенов и бонус за репост
Баланс, списание до генерации, автовозврат при ошибке, журнал `token_ledger`.
`verify_social_post`: каскад по **ссылке**, а не по скриншоту (ADR 0007) —
белый список площадок → анонимная загрузка страницы → сверка перцептивного
хеша → отдельный агент-проверяющий (ADR 0011). Ручной модерации нет.
Дедупликация по нормализованной ссылке.
**DoD:** баланс корректен при успехе, ошибке и повторной подаче той же ссылки;
журнал сходится с балансом.

### Фаза 9 — Админка полностью
Дашборд, участники, **диалоги с раскрытием вызовов инструментов**,
генерации (исходный запрос ↔ финальный промпт ↔ результат), журнал
начислений за репосты (только просмотр), аудит, версионирование
системного промпта с откатом.
Одна таблица на все разделы: поиск, сортировка, пагинация, обрезка
длинного текста с подсказкой, клик по всей строке.
**DoD:** по любому участнику видно, что он писал, что вызвал агент и что вышло.

### Фаза 10 — Прод, устойчивость, фестиваль
Docker Compose для prod, лейблы Traefik, бэкапы `pg_dump` по cron.
Мониторинг кредитов с алертом, очередь с честной позицией, нагрузочный тест.
Runbook на день фестиваля.
**DoD:** prod поднят на `bot.example.com`, smoke-тест пройден, runbook написан.
