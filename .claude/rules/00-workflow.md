# Рабочий процесс

## Перед началом любой задачи
1. Прочитай `docs/STATE.md` — там текущая точка.
2. Найди задачу в `docs/ROADMAP.md` и её фазу в `docs/phases/`.
3. Если задача меняет архитектуру — сначала ADR в `docs/decisions/`, потом код.

## Во время работы
- Работаем по фазам. Фаза закрывается только когда выполнен её **Definition of Done**.
- Не забегай вперёд: не пиши код фазы N+1, пока не закрыта N.
- Любое отклонение от плана фиксируется в `docs/STATE.md` в разделе «Отклонения».

## После задачи — обязательно
1. `pnpm typecheck && pnpm lint` — должно быть чисто.
2. Обнови `docs/STATE.md`:
   - что сделано (кратко, по фактам),
   - что следующий шаг,
   - открытые вопросы/блокеры.
3. Коммит по Conventional Commits: `feat(bot): ...`, `fix(admin): ...`, `docs: ...`.

## Continuity между чатами
`docs/STATE.md` — единственный источник правды о прогрессе. Он должен быть
написан так, чтобы новый чат без истории мог продолжить работу, прочитав
`CLAUDE.md` + `docs/STATE.md`. Не полагайся на память диалога.

## Чего не делать
- Не начинать рефакторинг «по пути», если он не в задаче.
- Не добавлять зависимости без записи в STATE.md с обоснованием.
- Не трогать prod-стенд для проверок.
