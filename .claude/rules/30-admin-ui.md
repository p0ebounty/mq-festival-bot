# Админка (веб-интерфейс)

## Жёсткое требование заказчика

**Никаких браузерных нативных элементов.** Всё кастомное.

Запрещено к использованию:

| Запрещено | Чем заменяем |
|---|---|
| `window.alert()` | кастомный toast (`sonner`) |
| `window.confirm()` | `<AlertDialog>` из shadcn/ui |
| `window.prompt()` | модалка с формой |
| нативный `<select>` | `<Select>` из shadcn/ui (Radix) |
| нативная валидация формы (`required`, `pattern`, всплывашка браузера) | `react-hook-form` + `zod`, ошибка рисуется под полем |
| `<input type="date">` нативный пикер | `<Calendar>` / `<DatePicker>` shadcn |
| `<input type="file">` голый | кастомная dropzone |
| нативный tooltip через `title=""` | `<Tooltip>` shadcn (или `<Truncated>`) |

На каждой форме обязателен `noValidate` на `<form>` — чтобы браузер не показал
свою всплывашку. Это правило проверяется линтером (см. ниже).

## Стек

- Next.js App Router + React + TypeScript
- Tailwind + **shadcn/ui** (есть установленный skill `shadcn` — пользуйся им)
- `react-hook-form` + `zod` для форм
- `@tanstack/react-query` для серверного состояния
- `sonner` для тостов, `recharts` для графиков

## Разделы

1. **Дашборд** — генераций за сегодня/всего, активные пользователи, расход
   кредитов kie.ai, средняя длительность, доля ошибок.
2. **Пользователи** — список, поиск, карточка: профиль Telegram, баланс токенов,
   история генераций. Действия: начислить/списать токены, забанить.
3. **Диалоги** — просмотр переписки пользователя с агентом, с раскрытием
   **вызовов инструментов**: какой tool, с какими аргументами, что вернул,
   сколько занял. Это ключевой инструмент отладки агента.
4. **Генерации** — галерея: исходный запрос, финальный промпт, результат,
   статус, стоимость, время. Фильтры по статусу/пользователю/дате.
5. **Настройки** —
   - ключ kie.ai: заменить на лету, без рестарта, с кнопкой «проверить ключ»
     (дёргает `GET /api/v1/chat/credit`);
   - модель агента (модель картинок — в коде, ADR 0006);
   - экономика: стартовый баланс, цена генерации, бонус за репост, лимит
     слабых подтверждений;
   - хештеги для страницы результата.

   ⚠️ **Системного промпта в админке НЕТ** — по решению владельца.
   Промпт это характер бота, а не крутилка: менять его вслепую на живом
   фестивале опаснее, чем выкатить изменение. Живёт в
   `packages/core/src/agent/prompt.ts`.
6. **Начисления за репосты** — журнал проверок постфактум: что прислали, какой был вердикт, каким доказательством подкреплён. Только просмотр — **ничего не согласовывается руками**, бот автономен.
7. **Аудит** — журнал действий администратора.

## Правила UI

- Тёмная и светлая темы, переключатель. Ничего не «прибито» цветом.
- **Таблица в приложении одна** — `components/data-table.tsx` на
  `@tanstack/react-table` (v8; девятая ещё меняет API). Свою таблицу на
  странице не собираем: поведение обязано быть одинаковым везде.
  В ней уже есть поиск, сортировка и пагинация.
- **Длинный текст обрезается многоточием**, а не растягивает таблицу.
  Полный текст показывает `<Truncated>` своей всплывашкой — и только если
  текст действительно не поместился.
- **Кликается вся строка**, а не одна ссылка в ней. Ссылки внутри строки
  оборачиваются в `<CellLink>`: он гасит всплытие. Роль строки при этом
  НЕ подменяется — `role="link"` затирает implicit `role="row"`.
- **Никаких символов вместо иконок.** Стрелки, галочки, треугольники —
  только `lucide-react`. Ссылка-действие («назад к списку») — это `Button`
  с подложкой, а не голый текст.
- Любое разрушающее действие — через `<AlertDialog>` с явным названием объекта.
- Пустые состояния и состояния загрузки (skeleton) обязательны, не «пустой экран».
- Ошибка сети — понятный блок с кнопкой «повторить», не белый экран.
- **Живое обновление включено везде.** `LiveUpdates` в layout слушает
  `/api/events` (SSE) и зовёт `router.refresh()`. Источник событий — сама
  база: триггеры шлют `pg_notify` при любой записи. Новую страницу
  подключать не нужно, она обновляется сама, если это серверный компонент.

## Линт-защита

В `apps/admin/.eslintrc` включить `no-restricted-globals` / `no-restricted-syntax`
на `alert`, `confirm`, `prompt` и на `<select>`/`<option>` в JSX — чтобы
требование заказчика нельзя было нарушить случайно.

## Radix, а не Base UI

Проект инициализирован с `--base radix` (стиль `radix-nova`), компоненты
импортируют `radix-ui`. Значит кастомный триггер оборачивается через **`asChild`
с children**, а НЕ через проп `render` (это API Base UI):

```tsx
// ✅ правильно (Radix)
<AlertDialogTrigger asChild>
  <Button aria-label="Выйти"><LogOutIcon /></Button>
</AlertDialogTrigger>

// ❌ неправильно — триггер просто не отрендерится, ошибок в консоли не будет
<AlertDialogTrigger render={<Button ... />} />
```

Тихий отказ: кнопка исчезает из DOM без предупреждений. Ловится тестом
`e2e/no-native-ui.spec.ts`.
